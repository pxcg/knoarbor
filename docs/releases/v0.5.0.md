# KnoArbor v0.5.0

KnoArbor v0.5.0 is an onboarding and diagnostics release. It keeps the multi-source ingest foundation from v0.4 and focuses on making local setup, readiness checks, API boundaries, and report inspection easier to trust before broader feature expansion.

## Highlights

- **Unified readiness diagnostics**
  - `knoar doctor` and `GET /doctor` now expose one read-only diagnostic contract.
  - Checks cover config loading, vault structure, model environment variables, connector discovery, optional document preprocessing, and recent run state.
  - The diagnostic layer does not call semantic models and does not write wiki pages.

- **Management UI preflight**
  - The local web console now surfaces readiness status on the overview page.
  - The run page uses the same doctor result for preflight instead of maintaining a separate UI-only readiness heuristic.
  - Blocking errors and warnings are visible before starting long ingest or lint runs.

- **Clearer public API boundary**
  - The API docs now identify the stable v0.x public alpha surface:
    - `GET /health`, `GET /doctor`
    - `POST /ingest/*`
    - `POST /lint/run`
    - `POST /query/search`, `POST /query/feedback`, `GET /query/trends`
    - `/runs/*`
  - `/ui/api/*` is explicitly documented as an internal local-console API.

- **More readable reports**
  - Report label localization now handles compact metric keys without underscores, such as `runid`, `writtenpages`, and `tokenspersecond`.
  - Canonical Markdown reports remain unchanged; the improvement is in the UI presentation layer.

- **Stronger release gates**
  - `scripts/dev-check.sh` now runs frontend build, Python tests, read-only `doctor`, and package build.
  - `scripts/clean-clone-smoke.sh` also verifies read-only diagnostics in a clean clone.

## Validation

- `cd web && npm run build`
- `uv run python -m unittest discover -s tests`
- `uv run knoar --config config.example.yaml doctor --json`
- `scripts/dev-check.sh`

Additional live-model validation:

- A temporary vault was initialized from a fresh config.
- `examples/agent-loop.md` was copied into `wiki/raw/notes`.
- The flow `doctor -> ingest --connector markdown --write -> lint-run --mode structural -> query "Agent Loop 是什么？"` completed successfully.
- The temporary smoke run generated wiki pages, reports, and relevant query context, then the temporary directory was removed.

## Known Boundaries

- KnoArbor remains an alpha, local-first, single-user project.
- Query returns structured local context for a host AI; it does not generate the final chat answer.
- Same-vault write-capable workflows are serialized by the local queue.
- Deterministic lint scans intentionally keep full-content ownership in maintenance because they validate page bodies and page contracts.
- Built-in vector search, hosted SaaS deployment, user authentication, and bundled MinerU runtime remain out of scope.

## Upgrade Notes

- Package metadata is now synchronized at `0.5.0`.
- Public high-level workflow API paths remain stable for the v0.x alpha line.
- Existing local configs should continue to work; no config migration is required for this release.
