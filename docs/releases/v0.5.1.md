# KnoArbor v0.5.1

KnoArbor v0.5.1 is a release-hardening patch for the v0.5 diagnostics line. It focuses on stable API contracts, public error envelopes, release-candidate validation, and clearer recovery visibility for long ingest runs.

## Highlights

- **Machine-readable API compatibility contract**
  - Stable public workflow, query, run, and diagnostic routes are now listed in `src/knoarbor/entrypoints/api_contract.py`.
  - API surface tests read that contract directly instead of duplicating route lists.
  - Removed deprecated n8n-era endpoints remain explicitly blocked from the OpenAPI surface.

- **Public error envelope for unexpected failures**
  - Unhandled FastAPI exceptions now return the shared KnoArbor error shape with `KA-INTERNAL-001`.
  - API clients no longer need to parse Python tracebacks for unexpected service errors.
  - The envelope preserves the stable fields used by CLI, UI, reports, and run monitors.

- **Ingest recovery visibility**
  - The management UI now highlights failed or partially failed ingest runs that can be recovered.
  - Recovery details include failed source counts, failed segment counts, document-processing failures, processed counts, written page counts, and recovery lineage when available.

- **Live release-candidate smoke test**
  - `scripts/live-release-candidate-smoke.sh` validates a temporary vault with a real DeepSeek-compatible model provider.
  - The smoke path covers Markdown ingest, Codex session ingest, structural lint, query, and the expected `KA-DOC-001` error when a non-Markdown file has no configured preprocessor.
  - The script is intentionally separate from the default release gate because it calls an external model API.

## Validation

The release candidate passed:

- `scripts/live-release-candidate-smoke.sh`
- `uv run python -m pytest tests/test_api_surface.py -q`
- `scripts/dev-check.sh`

The live smoke processed both Markdown and Codex sources, wrote four wiki pages in a temporary vault, produced a lint report, returned query results, and verified the missing-preprocessor error path.

## Upgrade Notes

- Package metadata is now synchronized at `0.5.1`.
- No config migration is required.
- Public v0.x workflow API paths remain stable.
- `/ui/api/*` remains reserved for the bundled management console and is not a stable external integration API.
