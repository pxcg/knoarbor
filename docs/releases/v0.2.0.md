# KnoArbor v0.2.0

KnoArbor v0.2.0 is an engine-foundation alpha release. It keeps the local-first workflow from v0.1 and focuses on making ingest, lint, query, runs, reports, and API behavior more observable and stable.

## Highlights

- **Machine-index-backed reads**
  - Query, graph, UI page summaries, and UI status page counts now use the machine index boundary.
  - Stale machine indexes are refreshed before index-backed readers use them.

- **Long-running workflow observability**
  - Runs now expose a fuller state vocabulary, including queued, waiting, writing, linting, cancelling, cancelled, failed, completed, and partially failed.
  - Run result policy maps successful workflow returns to completed or partially failed without embedding monitor logic inside ingest, lint, or query pipelines.
  - Reports and UI timelines now surface partially failed run details.

- **API and error consistency**
  - FastAPI HTTP exceptions use the shared public error envelope.
  - CLI errors use the same public error taxonomy.
  - Public API docs describe the v0.2 alpha compatibility boundary.

- **Query observability**
  - Query responses include richer trace/report metadata.
  - Query ledger records can be summarized through the new read-only `GET /query/trends` endpoint for repeated no-result or low-confidence gaps.

- **Write and indexing boundary cleanup**
  - Batch page writes update the machine index once at the pipeline boundary.
  - Transaction-boundary tests cover index update failures after page writes.

- **Management UI refinements**
  - Localized run statuses are displayed consistently across run monitors and reports.
  - The bundled console remains available at `/`, with `/ui` kept as a compatibility alias.

- Python package build passed.
- `scripts/clean-clone-smoke.sh` passed.
- Temporary vault smoke test passed for init, status, query, and query trends.

## Known Boundaries

- This is still an alpha release.
- Real semantic ingest and semantic lint quality still depend on the configured model provider.
- KnoArbor does not generate final chat answers; query returns context for host AI tools.
- Vector search, hosted deployment, built-in MinerU runtime, and SaaS-style authentication remain outside this release.
- Same-vault write-capable workflows remain serialized by the local queue to protect consistency.

## Upgrade Notes

- Public workflow paths and core semantics remain stable from v0.1.
- Response schemas may include additive fields.
- If you built integrations against `/query/search`, consider reading `/query/trends` for query-gap dashboards or future maintenance planning.
