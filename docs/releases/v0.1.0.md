# KnoArbor v0.1.0

First public alpha release of KnoArbor.

KnoArbor is an AI-native wiki engine that compiles multi-source information into a traceable, maintainable knowledge network, helping scattered knowledge grow like a tree.

This release establishes the first complete local loop:

```text
Raw sources -> Ingest -> Markdown wiki -> Lint -> Query context
```

## Highlights

- **Local-first AI Wiki engine**
  - Initialize a normal Markdown wiki vault.
  - Open generated pages in Obsidian or any Markdown editor.
  - Keep runtime wiki data outside the Git repository by default.

- **Multi-source ingest**
  - Markdown notes.
  - Hermes session exports.
  - Codex session exports.
  - OpenClaw session exports.
  - Claude Code session exports.
  - Single-file ingest for Markdown and preprocessed documents.
  - Optional MinerU-compatible document preprocessing for non-Markdown files.

- **Semantic wiki compilation**
  - Normalize raw inputs into a stable source contract.
  - Plan page-level operations.
  - Compile source digests and knowledge pages.
  - Review drafts before writing.
  - Segment long sources before semantic processing.
  - Write ingest reports and checkpoints.

- **Lint maintenance**
  - Deterministic scan for links, source chains, wiki structure, and graph health.
  - Semantic structural diagnosis.
  - Semantic quality diagnosis.
  - Maintenance review before applying changes.
  - Operation execution, verification, reports, and ledgers.

- **Query context for host AI tools**
  - Retrieval-only query pipeline.
  - Returns ranked pages, excerpts, source pointers, graph context, and a context pack.
  - Can write query reports for reproducible retrieval inspection.
  - Host tools such as Hermes, Codex, Claude Code, or CLI workflows remain responsible for final answer generation.

- **Local console, CLI, and API**
  - CLI commands via `knoar` and `knoarbor`.
  - FastAPI service.
  - Bundled React management console served at `http://127.0.0.1:8000`.
  - Generic local wiki skill template for AI tools that can call a local HTTP service.

- **Release engineering baseline**
  - Local development gate for frontend build, Python tests, and package build.
  - Release-readiness gate for branch, dirty-tree, required-file, and tracked-runtime-artifact checks.
  - Clean-clone smoke gate that validates the project from a temporary clone without calling model-provider APIs.

## Installation

Requirements:

- Python 3.12
- uv
- One OpenAI-compatible model provider

```bash
git clone https://github.com/pxcg/knoarbor.git
cd knoarbor
uv sync
cp config.example.yaml config.yaml
cp .env.example .env
```

Set a provider key in `.env`, then initialize and run:

```bash
set -a && source .env && set +a
uv run knoar init --vault ./wiki
uv run knoar serve
```

Open:

```text
http://127.0.0.1:8000
```

## Quick Checks

```bash
uv run knoar status --vault ./wiki --json
uv run knoar ingest --write
uv run knoar lint-run --mode full --apply-reviewed
uv run knoar query "Agent Loop 是什么？"
```

## Not Included Yet

- Hosted SaaS deployment.
- Built-in vector database.
- Built-in chat answer generation.
- Built-in MinerU model/runtime.
- User login, multi-user permissions, or TLS termination.
- Packaged external workflow templates.

## Known Limitations

- This is an early alpha release. v0.1 workflow API paths and core semantics are intended to remain stable during the v0.1 line, while schemas may still receive additive fields before a later stable release.
- Query is retrieval-only; it intentionally does not generate final chat answers.
- Non-Markdown files require a configured document preprocessor.
- Large vaults currently use local indexing rather than a vector store.
- Local runtime data can contain private content and should not be committed.

## Release Acceptance Criteria

The first public alpha is considered ready when it satisfies these boundaries:

- A new user can clone the repository, install dependencies with `uv sync`, initialize a local vault, start the service, and open the management console.
- The core local loop works through CLI/API/UI: ingest supported sources, lint the generated wiki, and query context from the maintained wiki.
- Markdown and AI-session connectors are available; non-Markdown documents either pass through a configured MinerU-compatible preprocessor or fail with an explicit configuration error.
- Runtime artifacts are excluded from the repository, and clean-clone validation can reproduce tests, frontend build, package build, and basic CLI smoke checks.
- Reports, ledgers, checkpoints, file locks, run monitoring, and structured logs make long-running operations inspectable.
- Query remains retrieval-only. Final answer generation stays with the host AI tool.

Capabilities outside these boundaries should be treated as post-v0.1 work, not release blockers.
