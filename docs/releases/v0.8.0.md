# KnoArbor v0.8.0

KnoArbor v0.8.0 is an API contract and token-observability release. It keeps the v0.7 management-console foundation and focuses on making the local HTTP API clearer for integrations, workflow tools, and host AI skills. It also makes semantic model cost visible directly in ingest and lint reports.

## Highlights

### Stable Public API Shape

The public workflow surface is now organized around stable capability endpoints:

```text
POST /ingest
POST /lint
POST /query
GET  /runs
GET  /wiki/pages
GET  /wiki/pages/content
GET  /wiki/pages/links
```

`/ingest` and `/lint` now use one response envelope for both queued and direct execution. This makes API clients easier to write because `flow`, `execution`, `status`, `run_id`, `run`, and `result` are always present at the top level.

### `vault_path` As The Public Path Field

Public API examples and clients now use `vault_path`. Older internal naming remains an implementation detail and should not be used by external clients. Run inspection endpoints can also resolve the configured vault automatically when `vault_path` is omitted.

### Token Usage And Cache Visibility

Ingest and lint reports now include a `Semantic Token Usage` section with:

- semantic call count;
- prompt tokens;
- cached prompt tokens;
- prompt cache rate;
- completion tokens;
- total tokens;
- semantic elapsed time;
- tokens per second;
- per-agent totals;
- per-call details.

This makes it possible to answer practical questions such as which semantic agent is expensive, which stage benefits from provider prompt caching, and whether a long ingest run is cost-effective.

### Prompt Cache Friendly Semantic Calls

Semantic calls now separate stable contract instructions from dynamic source payloads with a stable contract preamble. This is intentionally conservative: it improves prompt cache opportunities without changing agent responsibilities, semantic schemas, or page-writing behavior.

## API Notes

The intended public API surface is documented in [API Reference](../API.md). Internal UI endpoints under `/ui/api/*` remain reserved for the bundled console and are not stable integration endpoints.

The main wiki page APIs are:

```text
GET /wiki/pages
GET /wiki/pages/content
GET /wiki/pages/links
```

The previous prototype-style split between single-page and page-collection routes has been tightened before a stable v1 API is declared.

## Upgrade Notes

- No configuration migration is required from v0.7.0.
- API clients should prefer `vault_path` in request bodies and query parameters.
- Restart `uv run knoar serve` after upgrading so the bundled UI assets and OpenAPI schema are refreshed.
- Runtime wiki data remains ignored by git. Do not commit `wiki/`, `.env`, `config.yaml`, or private connector source directories.

## Known Boundaries

- KnoArbor remains local-first and single-user in this alpha line.
- Query remains retrieval-only; host AI tools generate the final answer.
- Prompt cache effectiveness depends on the configured model provider. The report records returned cache metrics when the provider exposes them.
- Internal `/ui/api/*` routes may still change between alpha releases.
