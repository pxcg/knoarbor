# KnoArbor v1.2.0

KnoArbor v1.2.0 focuses on configuration lifecycle and multi-vault usability. It lets one local service manage multiple named knowledge bases while keeping write workflows scoped and traceable.

## Highlights

- **Multi-vault profiles**: configure multiple knowledge bases with stable `vault_id`, display name, and local path.
- **Vault-aware UI and runtime context**: the console, runtime discovery, and status surfaces can show the active vault and configured vault list.
- **Multi-vault query**: query one vault, a selected vault set, or all configured vaults. Query results include `vault_id`, `vault_name`, and `vault_path` so host AI tools can continue with the right vault.
- **Single-vault writes**: ingest and lint now accept configured vault selection, but each write-capable run still targets one vault to keep locks, checkpoints, reports, and provenance simple.
- **Runs and reports across vaults**: run/report listing can aggregate configured vaults while single-run inspection remains scoped to one vault.
- **Skill integration polish**: the bundled local skill now includes UI metadata, icons, retrieval guidance, natural-language command examples, runtime discovery, and vault-aware page drilldown.
- **Configuration consistency**: CLI, API, UI, and skill flows now share the same `config_path` / `vault_id` / `vault_path` semantics.

## Public Interface Notes

The 1.2 release keeps the 1.0 public API surface and extends it with additive multi-vault fields and selectors:

- Read APIs can use `vault_path` directly or `config_path` plus `vault_id`.
- `/query` can use `all_vaults: true` or `vault_ids: [...]`.
- `/runs` and `/reports` can list across configured vaults.
- `/ingest` and `/lint` remain write workflows for one selected vault per request.

Internal `/ui/api/*` routes remain reserved for the bundled console.

## Upgrade Notes

- Existing single-vault configurations continue to work.
- To add multiple knowledge bases, define `vaults.profiles` in `config.yaml` and set `vaults.default`.
- Prefer `vault_id` for configured vaults and `vault_path` for one-off automation.
- Host-AI skill users should sync the updated `integrations/skills/knoarbor-local` bundle so page reads and reports preserve vault context.
