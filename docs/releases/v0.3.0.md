# KnoArbor v0.3.0

KnoArbor v0.3.0 is a reliability-and-evaluation alpha release. It keeps the v0.2 local engine foundation and focuses on making semantic workflows, reports, long-source ingest, and release validation easier to trust without relying on live model calls for every review.

## Highlights

- **Semantic execution reliability**
  - Semantic contracts now run through the centralized `SemanticRunner` reliability boundary.
  - Retry policy, invalid structured-output handling, error classification, run events, and token/latency metrics stay out of individual agents and prompts.

- **Golden harness coverage**
  - Query context packs and query report rendering have deterministic golden fixtures.
  - Source segmentation and segmented ingest aggregation have deterministic golden fixtures.
  - Lint deterministic scan, semantic structural maintenance, operation verification, rescan behavior, and lint run report rendering have deterministic golden fixtures.

- **Long-source ingest quality datasets**
  - Long Markdown notes and Codex-style chat sessions now have golden datasets.
  - The datasets lock source digest merging, page-boundary variety, written page links, and ingest report structure.
  - These fixtures help review prompt, schema, and pipeline changes without depending on a live model provider.

- **Query gap visibility**
  - Query gap trend information is available through API and the management UI.
  - Repeated no-result or low-confidence query patterns can inform future maintenance planning.

- **Release gate consolidation**
  - `scripts/release-check.sh` now runs the release gate sequence: local development gate, release-readiness check, and clean-clone smoke validation.

## Validation

The release candidate should be checked through:

- `scripts/dev-check.sh`
- `scripts/release-readiness.py`
- `scripts/clean-clone-smoke.sh`
- `scripts/release-check.sh`
- one small live-model smoke test for ingest, lint, and query when a model provider is available

At the time this release note was prepared, local gates covered frontend build, Python tests, and package build. Live-model validation depends on the user's configured provider.

## Known Boundaries

- This is still an alpha release.
- KnoArbor does not generate final chat answers; query returns context for a host AI.
- Vector search, hosted deployment, bundled MinerU runtime, and SaaS-style authentication remain outside this release.
- Same-vault write-capable workflows remain serialized by the local queue to protect consistency.
- Golden fixtures verify deterministic contracts and representative quality boundaries; they do not replace user review of real vault content.

## Upgrade Notes

- Public workflow paths and core semantics remain stable from v0.2.
- Response schemas may include additive fields.
- Integrations should continue to use the high-level workflow APIs under `/ingest/*`, `/lint/run`, `/query/*`, and `/runs/*`.
