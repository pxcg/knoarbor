# KnoArbor v0.9.0

KnoArbor v0.9.0 focuses on local runtime usability, host-AI skill integration, and release-ready observability. It builds on the v0.8 API contract work by making the active service easier for external tools to discover and by improving how users inspect runs, reports, and token usage from the bundled console.

## Highlights

### Runtime Endpoint Discovery

`knoar serve` now writes the active service endpoint to:

```text
.knoarbor/endpoint.json
```

This file records the resolved base URL, host, port, config path, and start time. Local skills and other host-AI integrations can read it instead of assuming that port `8000` is always available.

### Automatic Port Selection

When the configured service port is already occupied, `knoar serve` now searches for an available local port and prints the actual management UI and API docs URLs. The root URL remains the main UI entry, while `/ui` is preserved as an alias.

### Improved KnoArbor Skill Package

The `knoarbor-local` skill package now includes:

- a reusable `scripts/query.py` helper;
- `--check` for service and configuration diagnostics;
- runtime endpoint auto-discovery;
- examples for query requests and responses;
- installation, troubleshooting, and security notes.

This keeps the skill generic for host AI tools while avoiding hard-coded local paths.

### Token And Report Observability

The console now exposes token analytics and richer report views for semantic workflows. Reports include per-agent token fields, cache-related fields when providers return them, and clearer localized labels for common run metrics.

### Console Usability Refinements

The bundled management console has been refined around the main product flows:

- sources and document preprocessing;
- ingest;
- lint;
- query;
- knowledge base browsing;
- graph exploration;
- run reports;
- token analytics;
- settings.

## Validation

The release candidate passed the local release gate that does not require an external model provider:

```text
scripts/dev-check.sh
```

This includes:

- frontend production build;
- frontend dependency audit;
- frontend e2e smoke;
- Python lint;
- documentation link check;
- 323 Python unit tests;
- CLI diagnostics against an isolated temporary vault;
- Python package build.

Live DeepSeek smoke was not run for this candidate because the provider was unavailable during release preparation.

## Upgrade Notes

- No vault migration is required from v0.8.0.
- Restart `uv run knoar serve` after upgrading so `.knoarbor/endpoint.json` and bundled UI assets are refreshed.
- External skills and local tools should prefer `.knoarbor/endpoint.json` when available, then fall back to configured host and port.
- Runtime wiki data remains ignored by git. Do not commit `wiki/`, `.env`, `config.yaml`, raw private sources, or local connector paths.

## Known Boundaries

- KnoArbor remains local-first and single-user in the alpha line.
- Query remains retrieval-only; the host AI generates the final answer.
- Internal `/ui/api/*` routes remain reserved for the bundled console and may change between alpha releases.
